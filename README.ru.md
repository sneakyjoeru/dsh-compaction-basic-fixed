# dsh-compaction-basic-fixed — описание и установка (RU)

Компакция (суммаризация старой истории) для **DeepSeek Harness (dsh)** web. Исправленная копия
поставляемого пакета `@deepseek-ai/dsh-compaction-basic` **0.2.1-rc.2** с дефолтным поведением
**«компакция ровно на 80% окна контекста»**, без дополнительного headroom, плюс три фикса
для длинных сессий (метки `LOCAL OVERRIDE` в `lib/index.js`).

## Поведение

По мере роста давления токенов dsh сжимает самую старую историю в одно структурное саммари,
хвоставые сообщения оставляет дословно, а после подтверждённого переполнения окна — повторяет
запрос. `/compact` (если подключён `dsh-command-compact`) — ручное сжатие;
`dsh-compaction-tool-result-pruner` сначала режет слишком большие результаты тулзов
(без вызова модели, если реза хватает).

### Дефолты «компакция на 80%»

| Параметр | Здесь | В поставки |
|---|---|---|
| `thresholdRatio` | `0.8` | `0.8` |
| `headroomTokens` | `0` | `65536` |
| `retainRatio` | `0.2` | `0.16` |
| `maxTokens` | `4096` | следует за headroom (`65536`) |

Порог = `floor(min(0.8 · W, W − O))`, где `W` — окно контекста маршрутной модели, `O` — лимит
вывода запроса. Поставочные 65 536 токенов headroom на больших окнах утаскивают порок далеко
ниже 80% (на окне 131k — примерно 47%); при headroom `0` порок ложится ровно на 80%.

Все параметры переопределяются (глобально или по маршрутам через `modelPolicies`) — полный
список полей как у поставочного пакета, только дефолты другие.

## Установка

### Десктоп (нативная установка dsh)

1. Скопировать в каталог плагинов (`$DSH_HOME` — домашний каталог dsh, обычно `~/.dsh`):

   ```sh
   git clone https://github.com/sneakyjoeru/dsh-compaction-basic-fixed \
     "$DSH_HOME/plugins/dsh-compaction-basic"
   ```

2. В конфиге пользовательского профиля `$DSH_HOME/profiles/<profile>/cordis.patch.yml`
   заменить запись `compaction-basic` на монтирование по **абсолютному** пути:

   ```yaml
   - id: compaction-basic
     name: /абсолютный/путь/к/plugins/dsh-compaction-basic/lib/index.js
   ```

   На стандартном пресете `standard` запись живёт в группе `compaction` на *плане пресета*;
   монтирование только на хост-плане там — мёртвая конфигурация.

3. Перезапустить dsh. В boot-логе не должно быть строк `entries did not activate`.

### Удалённый сервер (dsh в Docker, например NAS)

1. Код — внутрь `$DSH_HOME` контейнера (в стеке `/volume1/docker/dsh` это
   `/volume1/docker/dsh/home`; `exec` в `dsh-web` или клонирование с хоста, который видит том):

   ```sh
   git clone https://github.com/sneakyjoeru/dsh-compaction-basic-fixed \
     "$DSH_HOME/plugins/dsh-compaction-basic"
   ```

2. Ту же строку монтирования добавить в `$DSH_HOME/profiles/web/cordis.patch.yml`.
3. Пересоздать контейнер — горячим монтажом работающий инстанц НЕ чинить:

   ```sh
   docker compose up -d --force-recreate dsh-web   # или ваш dsh-upgrade.sh
   ```

   Активные сессии сбросятся; после `ONLINE` в логе — перезагрузить страницу.
4. Проверка: `docker logs dsh-web 2>&1 | grep -c "entries did not activate"` даёт `0`; счётчик
   контекста показывает 100% на пороге 80% окна, компакция срабатывает именно там; `/compact` работает.

### Альтернатива: установка как пакета

```sh
cd dsh-compaction-basic && npm pack
dsh plugin --profile web add file:$PWD/dsh-compaction-basic-0.2.1-rc.2.tgz
```

После этого обязательно добавить строку монтирования по пути выше — чтобы монтировалась именно
локальная копия (с дефолтами 80% и тремя фиксами), а не поставочная.

## Повторный перенос после апгрейда dsh

Пакин закреплён за peer-зависимостями 0.2.1-rc.2. После каждого повышения dsh: сравнить этот
`lib/index.js` с новым поставочным `dsh-compaction-basic` и заново наложить три ханка
`LOCAL OVERRIDE` — источник истины по-прежнему поставочный файл.
